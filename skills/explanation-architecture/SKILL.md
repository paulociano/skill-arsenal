# explanation-architecture

## Objetivo

Projetar a arquitetura de uma explicação antes de escrever. A skill identifica o tipo de necessidade do leitor, escolhe a estrutura apropriada e define um outline que evita misturar aprendizagem, execução, compreensão conceitual e consulta rápida.

## Quando usar

- explicações longas ou complexas;
- documentação;
- materiais educacionais;
- artigos didáticos;
- respostas em que o usuário diz "me explica", "me ensina", "como faço" ou "quero uma referência";
- quando um texto está correto, mas desorganizado ou mistura propósitos.

## Quatro modos

### Tutorial
Objetivo: levar alguém a aprender fazendo.
- sequência guiada;
- contexto mínimo;
- resultado visível;
- erros esperados;
- progressão segura.

### How-to
Objetivo: resolver uma tarefa específica.
- pré-requisitos;
- passos diretos;
- decisões necessárias;
- verificação final;
- troubleshooting proporcional.

### Explanation
Objetivo: construir compreensão.
- modelo mental;
- mecanismo;
- relações de causa/efeito;
- analogias e contraexemplos;
- implicações e limites.

### Reference
Objetivo: consulta rápida e precisa.
- organização estável;
- termos exatos;
- tabelas/listas quando úteis;
- pouca narrativa;
- cobertura sistemática.

## Workflow

1. Identificar a pergunta real do leitor.
2. Escolher um modo dominante; misturar apenas quando houver motivo explícito.
3. Definir o que o leitor já sabe e o que precisa saber ao final.
4. Construir um outline:
   - promessa/pergunta;
   - conceitos ou passos indispensáveis;
   - exemplos;
   - exceções/limites;
   - verificação ou síntese.
5. Ordenar por dependência cognitiva, não pela ordem em que o autor descobriu o assunto.
6. Decidir quando usar analogia, exemplo trabalhado, comparação, tabela ou diagrama.
7. Encaminhar escrita para writing-quality e adaptação de profundidade para eli5/teach quando necessário.
8. Revisar se cada seção serve ao modo escolhido.

## Outline discipline

- título e subtítulos devem responder perguntas reais, não apenas nomear tópicos;
- cada seção deve ter uma função;
- remover capítulos que só repetem contexto;
- exemplos devem introduzir variação útil, não decorar;
- quando houver muitas ramificações, construir primeiro o caminho principal;
- outline não é índice automático: ele deve refletir a lógica de compreensão ou execução.

## Regras

- Não transformar toda explicação em tutorial.
- Não transformar reference em ensaio.
- Não usar analogia quando ela distorce o mecanismo.
- Não esconder limitações importantes para preservar simplicidade.
- Se o leitor só precisa da resposta, não obrigá-lo a atravessar uma aula inteira.
