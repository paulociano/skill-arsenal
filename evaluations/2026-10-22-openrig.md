# Avaliação: mvschwarz/openrig (2026-10-22)

- Fonte: https://github.com/mvschwarz/openrig (branch main, README, metadados e estrutura consultados em 2026-10-22)
- Tipo: framework/runtime de orquestração multiagente, não apenas uma Agent Skill.
- Classificação: **D — ferramenta técnica dependente de runtime externo**.
- Decisão: **REFERENCE_ONLY**. Não instalar OpenRig no ChatGPT, não criar skill duplicada e não alterar os owners existentes sem ganho metodológico demonstrado.

## O que entrega
CLI TypeScript `@openrig/cli` e daemon que coordenam equipes persistentes de coding agents (Claude Code, Codex e Pi conforme descrição do repositório; o README de instalação enfatiza Claude Code/Codex). Equipes definidas em YAML, papéis/assentos, tmux/TUI, contexto compartilhado, comunicação, tarefas e estados. Oferece bundles starter/workshop/factory e operação contínua vinculada ao repositório.

## Onde faz diferença
Projetos de desenvolvimento longos que têm vários agentes *reais* executáveis, sessões persistentes, filas/handoffs e necessidade de operação local observável. Não beneficia materialmente uma simples resposta no ChatGPT nem oferece por si só novos agentes internos neste ambiente.

## Dependências e portabilidade
Node.js 22 ou 24, npm, tmux, macOS/Linux; Windows por WSL2, sem suporte nativo. Requer Codex CLI e/ou Claude Code autenticado; suporte e testes WSL2 têm ressalvas no README. Setup modifica dotfiles/configurações (tmux, Codex, Claude) e pode adicionar hooks, trust, serviços e arquivos do workspace. Não presumir que GitHub connector, ChatGPT ou Codex em nuvem ofereçam o daemon/terminal do OpenRig.

## Comparação com Arsenal
- `multi-agent-orchestration`: já prevê ownership, isolamento, state, controle operacional e reviewer independente.
- `software-factory-operations`: já prevê fila durável, charters, quality gates, aprovação humana e revisão desacoplada.
- `agent-action-governance`: é a referência para least privilege e authorization boundaries.
- Ganho incremental: OpenRig **implementa** esses conceitos como produto local integrado, mas não apresenta, na evidência revisada, lacuna metodológica que justifique nova skill.

## Segurança (revisão estática parcial)
**CAUTION**. README declara que bootstrap pode conceder acesso amplo ao kernel (incluindo Codex com `danger-full-access`/`never`), editar confiança, hooks e arquivos de configuração, e ressalva que backups/rollback não são garantidos. Instalação usa pacote npm ou script remoto; nesta avaliação não foram executados nem auditados em profundidade todos os scripts/dependências. Preferir release pinada, backup, dry-run, escopo reduzido, provider explícito e revisão antes de setup. Não classificar código como seguro com base apenas no README.

## Quando reavaliar
Quando o usuário pedir implantar uma equipe persistente de coding agents localmente, especialmente no Windows/WSL2, com evidência de CLI autenticada e necessidades de sessões multiagente. Nesse momento avaliar execução real, ameaças, custos, permissões, integrações e testes; tratar implantação como projeto separado.

## Resultado
Registro informativo; nenhuma skill/stack criada ou alterada, pois conteúdo conceitual está coberto. OpenRig não foi instalado ou ativado.
